# Remaining risks and limitations

Honest register. "Not done" means not done, not "designed".

| Id | Risk / limitation | Impact | What it would take |
|---|---|---|---|
| R-1 | **No live vendor integration has been tested.** FieldRoutes, CallRail, Google, Meta, Microsoft and Fabric are mocks or published shapes | The first real export or API page will find shape surprises | A sandbox account and authorisation; contract tests against recorded real (redacted) payloads |
| R-2 | **Demo authentication.** A cookie picks the role | Anyone can act as any role in demo mode | SSO claims → Viewer; remove `/api/role` |
| R-3 | **One CRM account assumed.** `crm_customers` is keyed by `crm_customer_id` alone | Two brands on two FieldRoutes accounts with the same id would collide | Namespace CRM ids by account (schema migration + mapper change) |
| R-4 | **Merged / deleted CRM customers** are not detected (open since the audit, G-7/G-8) | Attribution can point at a customer the CRM merged away | Read FieldRoutes merge/delete signals; reconcile them |
| R-5 | **Hashing is not anonymisation.** Phones and emails are SHA-256 hashed, unkeyed | Re-identification by hashing candidate numbers | HMAC with a managed key; encryption at rest; agreed retention |
| R-6 | **No CSV/XLSX export of onboarding data exists.** If one is added, formula-like cells (`=`, `+`, `-`, `@`) must be neutralised | Formula injection in a downstream spreadsheet | Prefix with `'` on export; the profile already flags such cells |
| R-7 | **The schema assistant was evaluated on synthetic exports written by AI labelers**, not on real exports or by human domain experts | The ~2–2.5% held-out wrong-suggestion rate may not transfer | A small human-labelled set from real (redacted) exports; a v4 set after any rule change |
| R-8 | **Uploads stay capped at 50,000 rows.** A 1M-row backfill through the same compiler and intake was measured on one laptop (5,604 rows/s durable, exact totals, crash-safe resume; `PERFORMANCE.md`). 10M was not run; behaviour once data exceeds RAM is unknown | A real backfill needs an operator path and server-class measurement | A bulk backfill job built from `scripts/bench-backfill.ts`; a 10M run on production-like hardware with a replica |
| R-9 | ~~Benchmarks ran on Postgres with `fsync=off`~~ **Resolved 2026-11-11:** re-run durable (fsync and synchronous commit on): about 20% slower for batched loads, about 15% for one 50k publication | — | — |
| R-10 | **Model-backed AI is not evaluated.** The investigator's model mode and any LLM mapper remain untested (no key, by rule) | Claims about model quality would be unsupported | An approved key, data-handling approval, the same evaluation sets |
| R-11 | **Scenarios B and C are built on the data that exists** (`OPPORTUNITIES.md`), but follow-up activity, lead qualification, cancellation reasons and post-service retention are not in the data, and no intervention has been measured | Both journeys stop at "hypothesis"; on the seeded world neither pattern is supported | Outbound call log, CallRail qualification fields, CRM cancellation reasons; a randomised pilot |
| R-12 | Publication holds the exclusive lead-write advisory lock for its duration (seconds for 50k rows). The old table lock, which could deadlock, is gone | Live lead intake waits during a publication | Per-id locks, if publication becomes frequent |
| R-13 | **Uploads are parsed in-process**; no malware scanning, no per-user upload rate limit | One user can occupy a worker with large valid files | Background parsing job; rate limits; scanning at the edge |
| R-14 | **Leading-zero CRM ids are refused** where the held-out labeler expected them accepted as text | A real export padding ids will need a person to confirm | A confirmed "strip padding" transform, recorded in the mapping version |
| R-15 | **Retention purge is lazy plus the worker loop**; with neither running, cells persist past 24 h until the next onboarding request | Short-lived over-retention | A scheduled job in production |
| R-16 | **CallRail does not resend webhooks**, and calls have no `updated_at` (`VENDOR-CONTRACTS.md` C-4a, C-5) | A call delivered while intake is down is lost silently; a late Post-Call can overwrite a Call Modified | A date-range poll to recover drops; re-fetch each call by id after 20 minutes |
| R-17 | ~~calls@1.2 and ads@1.2 are staged, not active~~ **Resolved 2026-11-12** (`EVIDENCE-INTELLIGENCE.md` §1, §5): both are active. An excluded state keeps outbound, spam and not-a-lead calls as evidence outside every lead metric, across revisions, replays and identity links. Non-USD spend is refused, and already-stored rows were withdrawn by migration `0019`. ~~A feed that states no currency is assumed USD~~ **Resolved 2026-11-12** (`FINANCIAL-EVIDENCE-GRAPH.md`): unstated currency is excluded at intake and listed; it counts only under a per-account rule an engineer proposes and a different approver authorizes, and a revoke excludes it again | — | — |
| R-23 | **Partly resolved 2026-11-12** (`PROOF-CARRYING-REPORT.md`): a 62-case investigator set was written and frozen before the code met it; first contact was committed unchanged (20/30 correct outcomes, 26/57 critical false accepts). **Still open:** the set has since been used to improve the code and is now a regression suite; model-backed investigation is still unevaluated (no key) | A fresh measurement needs a new set | A v2 frozen set, ideally human-labelled; a key and data-handling approval for model mode |
| R-24 | **Mostly resolved 2026-11-12:** claims are proved against typed facts, not matched by number; signs, number words, ratios, scaled figures, quoted names and other currencies are read or refused; model text with any unread part is rejected (the closed reading). **Still open:** the closed reading is a list of patterns (R-27) | — | — |
| R-25 | ~~Only paid CAC and paid spend are traceable~~ **Resolved 2026-11-12:** collected cash, refunds, gross, new-customer collections, at-risk revenue, attribution coverage and brand rollups are traced to the cent, with invariants that can fail. ~~The cash trace has no page~~ **Resolved 2026-11-12:** `/branches/[id]/trace?metric=collected`, linked from the branch's Collected tile; browser journey J2 checks it against a reference computed from the raw source payloads, J5 against a refund delivered through intake | — | — |
| R-26 | **Partly resolved 2026-11-12:** Decision Lab verified-readiness states and targeted reliability signals are built. **Not built:** onboarding revision states (M4), identity tiers (M5) | Those workflows are as before this program | The next milestones |
| R-27 | **The closed reading is a list of patterns.** It rejects model text with a negation, verb, period, entity, figure form, currency, second measure or metric-changing word it does not read, but a wrong sentence in a shape no pattern names could still pass; it was tested on the AI-claims reviewer's cases and the regression suite only | A model in production could find a shape the patterns miss | A fresh adversarial set against the closed reading; a model run under the same checker once a key is approved |
| R-28 | **Currency rules are per account and undated.** A rule covers every day of the account, before and after it was authorized; a campaign whose spend is all held has no campaign row, so its spend is listed by ad account, not by branch; the two people are demo subjects (R-22) | A rule authorized for a later billing change also counts earlier unstated days | Effective-dated rules; SSO subjects |
| R-29 | **The workspace and readiness rules are coarse.** The Decision Lab reads the branch's latest tested workspace without ageing it out; branch-level rules repeat on every channel; the demo's business clock is frozen, so re-tests share a time | A stale workspace can keep a channel at NEEDS_REVIEW, or out of it | A freshness limit on workspaces; branch-level rules shown once |
| R-30 | **A release is `verified` at once, and monitoring runs only when a person asks.** ChangeGuard verifies the release in the same step; post-release monitoring (`monitorChange`) can move it to `degraded` / RECOVERY_REQUIRED, but only on a click. The VP pack expected a `monitoring` state first (4 checks; `vp-acceptance/evidence/ADJUDICATION.md`: the brief's wording was wrong) | If nobody clicks Monitor, evidence that later disagrees with a released mapping is not tied back to it | Scheduled monitoring for a window after each release; say "verified at release" in the status |
| R-31 | **Action Center dry-run evidence mixes scopes** (UX red team P1-6): company-wide totals sit beside branch figures without saying which is which | A reader can compare a branch number with a company number | Label each figure's scope; show branch and company in separate rows |
| R-32 | **Two approval models.** Action Center proposals (dry run → approve → execute) and ChangeGuard changes (preflight → approve → release) differ in steps and words. Each status now states the next step and who takes it (P1-8, partly fixed) | A user who learns one flow can misread the other | One state machine and vocabulary for both |
| R-33 | **A refused page returns HTTP 200.** Pages stream, so the status is sent before the scope check runs; the body is the 403 view (`<h1>403 — not in your scope</h1>`, now covered by the accessibility gate) | Monitoring or a crawler counts a refusal as success | Check scope before streaming (proxy), or Next's `forbidden()` once stable |
| R-34 | **UX debt from the red team (P2), not fixed:** Decision Lab about 4.3 s and Overview about 3.3 s to load (the A/A self-check recomputes on each load); some forms show raw server error text; ChangeGuard preselects branch B01; jargon (β, "evidenced touch"); long text blocks; the Overview lists 12 of 44 branches. **Fixed:** identical page titles, the 403 heading, the `/demo` scope leak, five misleading labels | Slower and harder first use | Cache the self-check per data version; plain-language pass with a real user |
| R-35 | **No human usability study was run.** The UX findings come from an AI walkthrough with seven personas, plus axe-core and a keyboard path. Persona completion: 3 completed, 3 partly, 1 found a leak (since fixed) | Nothing here shows business users find it intuitive | Five moderated sessions with Moxie marketing and finance staff |
| R-36 | **Five VP-pack disagreement groups need a human ruling:** VP-06 (a CRM office move: acquisition stays at the serving branch), VP-01 (H2 stays UNRESOLVED), VP-05 (B47 BLOCK versus UNSUPPORTED), VP-10 (a guest is refused currency rules: a change to the brief's role table, kept for least privilege), and the release state (4 checks: the product says `verified` at release, two independent readers expected `monitoring`; the person ruling wrote both the brief and the product, R-30). One AI designer wrote the pack; the runner and system share an author | The disagreements may be product judgement, not defects | A Moxie owner rules on each; a v2 pack labelled by a person |
| R-37 | **CRM payments and calls are ordered by receipt, not by a source clock.** Payments carry no `dateUpdated`, so a payment version is ordered by when it arrived (so void → successful → void is never lost). An identical older copy delivered late becomes current again: an old "successful" copy of a payment voided since would count as cash again until the next delivery. Calls have no modification time either (VENDOR-CONTRACTS C-5) | Late duplicate deliveries can resurrect a superseded payment state | A vendor field that orders payment versions; or treat voided as terminal unless the vendor re-sends after it |
| R-38 | **Template claims are trusted unless contradicted.** `judge()` (lib/ai/proof.ts) marks a template-written claim SUPPORTED when nothing contradicts it, even when some propositions are not proved; only model text is held to the closed reading. The UI showed "supported" beside "0 of 2 propositions follow" (UX-FINDINGS). The VP pack's AI checks ran in template mode only | A template sentence with an unproved part reads as verified | Show such claims as "written from a calculation" rather than "supported"; hold templates to the same reading |
| R-39 | ~~One paid call credited every customer sharing its phone~~ **Fixed 2026-11-12** (independent review finding 1): a lead credits a customer only when its phone and email match no other customer, or a reviewer accepted the pair; a rejected pair never credits (migration 0022; `tests/integration/shared-phone-credit.test.ts`, red first: 3 paid customers where 1 was right). The attribution trace now has an invariant that fails if a credited lead is ambiguous | Customers sharing a phone count as not attributed until a reviewer decides | Review the identity-conflict queue |
| R-18 | **Assistant confidence is not calibrated.** All six held-out errors were stated as high confidence (`AI-EVALUATION.md`) | A confidence label cannot be used to skip review | More held-out data per bucket; review required regardless of confidence (today's rule) |
| R-19 | **Google Ads fractional conversions are refused** (the column is an integer) | Data-driven-attribution days would be quarantined, visibly | A numeric column and a `reporting.*_v2` view |
| R-20 | ~~The B09 four-minute browser path is intermittent, and every production page logs React #418~~ **Resolved 2026-11-11:** three separate causes, each fixed with a test that fails without the fix (`VERIFICATION.md`, "R-20"). B09 path **10 / 10** on the production server | Execution and dry run still take about 5 s each on the seeded world (measured over HTTP) | Profile the reproject + reconcile + snapshot path if a presenter finds 5 s too slow |

First contact: 0 false approvals, 0 critical failures, 25/25 required refusals, 2 missed reviews and 5 false blocks; 4 defects fixed with regression tests. **Still open:** one AI labeller, no human; the runner and system share an author; v1 is now tuned on and no longer held out. Mappings are not effective-dated; lead evidence exists only where leads carry the campaign id | Two labels the system disagrees with (HO-14, HO-18) are judgement calls a human should settle; a fresh measurement needs a new set | A v2 blind set, ideally human-labelled; effective-dated mappings if a mid-history remap is ever needed |
